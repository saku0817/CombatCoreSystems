# v1.4.5

## 変更前後と理由

| 対象 | 変更前 | 変更後 | 理由 |
|---|---|---|---|
| 弓の減衰 | 発射イベントforceを直接倍率化 | チャージ時間割合を復元し近接同様0.2+0.8c² | 依頼された近接同等の計算へ統一 |
| 効果トリガー | セット専用の5イベント | 武器・天賦・技・装備・セット・神心の共通基盤 | YAMLだけで複合効果を構成 |
| スタック | Buffスタックのみ | 所有者・定義・対象別の独立状態 | 照準・マーク・消費量分岐を表現 |
| 攻撃限定補正 | 持続Buff中心 | BEFORE_HIT用の計算コピー | 他対象・次の攻撃への漏れを防止 |
| 回復 | 回復量を計算・適用 | 同じ経路で実回復とオーバーヒールを通知 | 回復由来の効果を一貫して実行 |
| フィールド | 共通機構なし | 5tick監視、範囲内専用のBuff付与元 | 毎tick全検索と同名Buffの誤解除を回避 |
| actionsだけの新しい技 | 通常技ダメージが暗黙に有効 | actionsがあれば省略時damage-enabled=false | 回復専用技が意図せず攻撃しないようにする |
| override | 非対応 | 最後の有効な付与を優先して最終値固定 | 会心率100%固定などを再現 |

既存ATK基本式、防御式、属性反応表、レベル曲線は変更しない。旧effects形式・self-effects/target-effects・限界突破累積マージを維持する。

新しいスタック・フィールド・動的補正・発動回数はランタイム状態であり、ログアウト／リロード／再起動を越えて保存しない。既存の保存型Buffやプレイヤーデータは従来方式を維持する。

## 検証

単体テスト67件、Paper 26.2上の統合チェック116件を通過。弓チャージ、スタック分離・上限・期限、攻撃限定補正、回復・オーバーヒール、固定値補正、フィールドの重複・離脱・個別解除を確認した。Web APIでは新旧YAMLの保存、不正定義の拒否、ロールバック、元ファイルの復元を確認した。

Paper試験は実アイテム・実Mobと模擬プレイヤーによるサーバー側検証。Java／BE実クライアントでの操作・表示や、大人数での負荷試験は未実施。

## 更新手順

サーバー停止後、プラグインデータとワールドをバックアップしてJARを交換する。既存YAMLを削除する必要はない。新機能の定義は下記資料の例を参照し、`/ccsadmin reload`で検証する。不正な定義は適用せず、直前の有効な定義を維持する。
