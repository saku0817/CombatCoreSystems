# CombatCoreSystems v1.4.2

## 変更箇所・理由・変更前後

| 箇所 | 変更前 | 変更後・差異と理由 |
| --- | --- | --- |
| Mob HP | MinecraftのMAX_HEALTHへ設定値を直接代入し、1,024を超える値で失敗 | CCSの仮想HPとMinecraft表示用HPを分離。設定・ダメージ・回復・BossBar・Bossフェーズは仮想値を使用し、内部値だけ最大1,024へ比例縮尺 |
| 属性反応の数値色 | 反応を構成する2属性のグラデーション | 最後に付着させ、反応を発生させた属性1色 |
| 空撃ち | 対象不在時は失敗し、CT・コスト・自己効果なし | `controls.allow-empty-cast: true`で発動成功。CT・HPコスト・自己効果・発動演出を適用し、対象ダメージと対象効果だけ省略 |
| 発動可能音 | なし | CT終了によってスキル／必殺技が不可能から可能へ変わった時、本人に設定音を1回再生 |
| 設定更新 | 新しい項目は既存ymlへ追加されない | 起動・管理reload時に同梱既定値の不足項目だけ追加。既存値を維持し、変更前を`backups/config-migrations`へ保存 |
| BE入力 | PlayerDropItemEventが来ない経路ではログも発動もなし | Floodgateプレイヤーの選択中ホットバースロットがDROP系InventoryClickへ変換された場合に発動。デバッグ時は選択スロットの全クリック・操作・ドロップ分類も記録 |
| BE入力の差異 | インベントリ破棄は常に通常破棄 | BEで「現在選択中」のスロットを破棄すると補完によりスキル扱い。他スロットは通常破棄。補完は設定で無効化可能 |
| 装備ツールチップ | 機械的なステータス列とセットキー | レア度、部位、Lv、メインステ、サブステ値・強化回数・未開放、シリーズ名、2/4セット説明と発動状態、説明文の順 |
| 固定サブステ | 作成時ランダムのみ | 例を再現する`initial-substats`、`initial-upgrades`、`initial-unlocked-substats`を追加 |
| セット効果 | modifiersの値だけ | 表示用`description`を追加。攻撃側の`DEF_IGNORE`により「攻撃時に敵防御力を無視」を計算可能 |
| 神心ツールチップ | modifiers/rulesの内部キー列 | レア度、神心部位、複数の名前付き天賦と説明、自由loreの順 |
| 神心の通常属性 | 神心が武器設定を上書き | 武器の通常攻撃属性が無属性の場合だけ神心で変換。武器に指定がある場合は武器を優先 |
| 神心反応 | 既存反応の倍率変更のみ | 最後に付着させた指定属性の反応を、名前・範囲・参照値・属性倍率・耐性低下・持続・同一対象CTを持つ別反応へ置換可能 |
| 管理 | ymlをファイル管理画面等で直接編集 | 認証付き内蔵Webエディタを追加。保存前バックアップ、YAML・定義検証、失敗時の自動復元を実施 |
| 入力ログ | `/ccsadmin debug on` と `controls.debug-inputs` が別々 | debugコマンドでも入力・発動試行・成功・失敗理由を記録。本人のチャット・コンソール・debugファイルで確認可能 |
| ログ負荷 | 1行ごとにメインスレッドでファイル追記 | 最大4,096行のキューへ積み、1秒ごとに非同期でまとめて保存。停止時に残りを保存。上限超過時は省略件数を記録 |
| 説明文生成 | インベントリ監査のたびに全説明文を再構築 | 最大2,048件の表示キャッシュを再利用。アイテム値・セット数・設定再読込が変わると再生成。表示結果は同じ |
| Mob定義検索 | バニラMob定義を毎回全件検索 | EntityTypeで直接検索。設定再読込時だけ索引を再構築 |
| 神心反応CTの整理 | 反応のたびに全CTを走査 | 期限切れ整理を最大1秒に1回へ集約。CTの発動判定時刻は同じ |
| Web新規作成・保存 | 仮実装はファイル末尾に文字列を追加 | YAMLの正しい定義ルートへ追加。既存IDの重複を拒否。他の画面との保存競合も検出 |
| YAML生成 | YAMLを直接記入する必要があった | 9種類のフォームからYAML生成・ダウンロード。オフラインHTML版も同梱し、追加ポート不要のレンタル環境にも対応 |

## Mob仮想HP

```yaml
virtual-health:
  physical-cap: 1024
```

例えば設定HP 50,000、現在HP 25,000ならMinecraft内部は最大1,024、現在512として同期されます。表示とCCSダメージ判定は50,000／25,000です。既存の管理対象Mobは起動・チャンク読み込み時に移行します。環境ダメージや他プラグインの回復も、現在の内部HPから仮想HPへ換算して表示します。ただし、それらのダメージ量自体はMinecraft内部値で計算されるため、CCS戦闘ダメージと同じ尺度にはなりません。HP 50,000のMobへの内部ダメージ10は、仮想HPでは約488.28になります。

## スキル設定

```yaml
controls:
  allow-empty-cast: true
  bedrock-selected-slot-drop-skill: true
  debug-inputs: false
hud:
  ready-sound:
    skill:
      enabled: true
      sound: minecraft:block.note_block.pling
      volume: 0.8
      pitch: 1.2
    ultimate:
      enabled: true
      sound: minecraft:block.amethyst_block.chime
      volume: 0.8
      pitch: 0.8
```

初回装備時やログイン直後、別武器への持ち替えだけでは音を鳴らさず、同じ技のCT回復による遷移時に鳴らします。HUD表示を無効にしていても音の設定は有効です。判定間隔は`hud.update-ticks`です。

BE入力の検証手順:

1. v1.4.2 JARへ交換して再起動し、起動ログのバージョンと`Floodgate detected`を確認します。
2. ゲーム内で `/ccsadmin debug on 2m` を実行します（管理権限が必要）。
3. スキルを持つCCS武器を選択し、手持ちからのドロップとインベントリ内の選択スロットの破棄を別々に試します。
4. `[DEBUG:skill-input]` の `drop` / `inventory click` / `bedrock selected-slot fallback` / `cast attempt` / `cast success` / `cast rejected` を確認します。
5. `cast rejected reason=...` なら発動条件を調べます。入力イベント自体が記録されない場合は、Geyser/Floodgateのバージョン・設置場所（Paper側／プロキシ側）・端末・操作方法とログを比較します。
6. `/ccsadmin debug off` で終了します。ファイルは `plugins/CombatCoreSystems/logs/debug/YYYY-MM-DD.log` です。

`controls.debug-inputs: true` は全プレイヤーの入力をコンソールへ出す別の方法です。ゲーム内debugを有効にしたプレイヤーについては二重出力を避けます。GeyserがBukkitイベントへ一切変換しない操作は、プラグインから検出できません。補完にはPaper側からFloodgate APIへアクセスできることが必要です。BE実機での修正完了は未確認です。

## 装備・セット・神心

同梱の`equipment.yml`、`sets.yml`、`divine_hearts.yml`に、依頼された「虚構の旅人」と「火神の神心／烈日」を再現するコメント例があります。割合は`0.10 = 10%`です。

主要な追加キー:

- `equipment.ID.initial-substats.STAT`
- `equipment.ID.initial-level`（省略時1。作成時のみ、最大レベル以下）
- `equipment.ID.initial-upgrades.STAT`
- `equipment.ID.initial-unlocked-substats`
- `sets.ID.name`
- `sets.ID.two-piece.description`
- `sets.ID.four-piece.description`
- `sets.ID.*.modifiers.DEF_IGNORE`
- `divine-hearts.ID.talents.TALENT.name/color/description`
- `divine-hearts.ID.rules.reaction-override.source-attribute/id/name/radius/cooldown-seconds`
- `divine-hearts.ID.rules.reaction-override.damage.reference/multiplier/attribute`
- `divine-hearts.ID.rules.reaction-override.resistance-down.attribute/amount/duration-seconds`

表示文は`messages.yml`の`equipment-tooltip`と`divine-heart-tooltip`で変更できます。例の装備は作成時Lv.9、最大Lv.25、メイン会心ダメージ60%、サブステ3つ開放の状態を再現します。作成時の強化回数と数値は独立して指定します。既存アイテムへ初期値を遡って適用しません。天賦の`description`は表示用で、効果は`modifiers`と`rules`で設定します。

## Webエディタ

初期状態は無効です。`config.yml`で次を設定してサーバーを再起動します。

```yaml
web-editor:
  enabled: true
  bind: 0.0.0.0
  port: 8765
  threads: 2
  token: 32文字以上の推測されにくい値へ変更
```

ブラウザのBasic認証では、ユーザー名は任意、パスワードに`token`を入力します。画面には以下があります。

- ダッシュボードと定義ID一覧
- 武器、装備、セット、神心、Mob、バニラMob、Boss、バフ・デバフ、属性・属性反応の編集
- 定義IDの一覧選択、新規作成テンプレート、YAMLダウンロード
- 複合成分の参照HP/ATK/DEF・属性補正・防御無視・耐性・会心を指定できるダメージシミュレータ
- 名前・レア度・説明・天賦・スキル・必殺技などのリアルタイムプレビューと選択定義の全キー表示

編集はYAML形式です。プレビューは選択した設定の表示確認用で、Minecraftの描画と完全一致するものではありません。プレイヤー依存のセット発動状態・現在レベルは実ゲームで確認してください。新規作成は`mobs: {}`などの空マップにも正しく追加します。入力を350ms待ってから解析し、古い解析結果は採用しません。

保存対象はCCSが管理する既知のymlだけで、2 MiBを上限とします。保存前ファイルは`plugins/CombatCoreSystems/backups/web-editor/<時刻-識別子>/`へ作られます。YAMLまたは参照定義が不正なら元へ戻します。読み込み時のハッシュと保存時のファイルが異なる場合はHTTP 409で保存を拒否するので、他の画面の変更を確認して再読込してください。保存と定義再読込はコマンドreloadとの競合を防ぐためサーバースレッド上で直列化します。Web保存では不足項目の補完を実施せず、入力内容のまま検証します。

レンタルサーバーでは、管理パネルで追加TCPポートを割り当て、そのポートを`port`へ指定します。ホスト提供のHTTPSリバースプロキシ、または管理者専用のSSHポート転送などを使って接続します。内蔵サーバーはHTTPなので、インターネットへ直接公開してトークンを平文送信しないでください。追加ポートも安全な接続経路も提供されないレンタルプランでは、内蔵Webエディタは利用できず、管理パネルのファイル編集を使う必要があります。Web機能のenabled/bind/port/threads変更にはMinecraftサーバー再起動が必要です。tokenは設定再読込後の次のリクエストから切り替わります。

## YAML生成・オフライン利用

Web画面の「YAML生成」で種類を選び、ID・名前・数値・説明などを入力して「YAMLを生成」を押します。武器／装備／セット／神心／Mob／バニラMob／Boss／バフ・デバフ／属性反応の9種類に対応します。武器のスキル・必殺技、神心の反応置換もフォームから追加できます。生成されたYAMLは編集・ダウンロードできます。

生成はサーバーへ自動保存しません。オンライン版では「既存設定の編集欄へ追加」で既存定義を残して追加し、「検証して保存」で反映します。既存IDの上書きは拒否します。この追加操作ではコメントの書式が整形されます。参照するバフやセットは別ファイルにも定義してください。部位ごとの使用可能なメインステータスなど、定義の詳細検証はサーバー保存時に行います。

Release Assetsの`CombatCoreSystems-YamlGenerator-1.4.2.html`をダウンロードしてブラウザで開くと、ネット接続なしで同じ生成機能とダメージシミュレータを使用できます。Web画面から「オフライン生成ツールを保存」で取得することもできます。ライブラリのCDN読込はありません。

追加ポートを提供しないレンタルプランでは、このHTMLで作成した`.yml`をサーバーの管理パネルから配置してください。**生成ファイルは1つの定義を含むので、既存ファイルへそのまま上書きせず、同じルート（`weapons:`など）の中へ統合してください。** 編集前ファイルをバックアップしてから`/ccsadmin reload`で検証します。

## 自動設定移行

起動または`/ccsadmin reload`時、同梱設定にあり既存ファイルにない設定キーを追加します。同名の既存値や独自定義は上書きしません。既存の武器・Mob・バフ・反応などの定義ルート内は自動補完せず、削除したサンプルを復活させません。新しい定義用の任意キーは実装側の既定値で扱い、必要なものを管理者が設定します。不正YAMLやバックアップ失敗時は書き込みません。保存は一時ファイルから置換します。BukkitのYAML保存処理により空白や引用符の表現が整形される場合があります。

## 検証

自動テスト35件と配布ビルドが成功しました。Paper 26.2で起動・設定移行、HP 50,000のMobと内部HP 1,024の分離、Web認証・読み込み・不正YAML拒否・不正定義の復元・正常保存・競合拒否を確認しています。

オフライン版は9種類のYAML生成とダウンロード、引用符と複数行説明の保持、入れ子の配列・マップの保持を検証し、生成物10ファイルをJavaのYAMLパーサーでも読み込みました。外部通信・JavaScriptエラーがないこと、シミュレータの複合ダメージ315・会心時473も確認済みです。

BE実機のGeyser/Floodgate入力、プレイヤー操作による装備表示・音・空撃ち、実レンタル環境のポート・HTTPS設定は未確認です。BEでBukkitイベント自体が発生しない経路は、CCSだけでは捕捉できません。
