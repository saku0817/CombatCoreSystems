# v1.4.3 変更内容

## 変更前後と理由

| 箇所 | 変更前 | 変更後・理由 |
| --- | --- | --- |
| ドロップ入力 | CRAFTINGビューのみ | CREATIVEも対応。クリエイティブが判定で除外される不具合を修正。除外理由を入力ログへ追加 |
| 操作時の監査 | 通常クリック・採掘のたび全所持品を監査 | アイテム変更イベント時に監査。キャンセル済みドロップでは監査しない |
| ステータス取得 | HUD・技・ダメージで同じtickに繰り返し再計算 | 同一tick内だけ結果を共有。設定変更・明示的無効化で失効、次tickは再計算 |
| PDC読取 | 読取のためItemMetaを複製 | 読取専用PDCへ直接アクセス |
| 自動スポーン | 未読込の遠方チャンクを同期読込・生成し得る | 読込済みチャンクだけ候補にする。未読込地域には自動スポーンせず、サーバースレッド停止リスクを軽減 |
| Lore | クライアントの斜体・紫色が継承される | 白・斜体なしを基準にし、明示した色・italicは保持 |
| メニュー頭 | プロフィール設定時の標準名が表示され得る | スキン設定後にGUI名を再設定。オンラインの既存プロフィールを使用 |
| 新生回帰 | 条件未達で無言 | Lv.100未達・戦闘中を表示。確認画面でも戦闘状態を再確認 |
| ダメージチャット | なし | configで有効化すると本人だけへ表示。TextDisplayを無効にしても利用可能 |
| 限界突破定義 | 一部の倍率・CTのみ上書き | 0～5段階の武器定義を累積マージし、基本ステータス・天賦・技・説明を一貫して適用 |
| 矢の武器定義 | 武器IDだけ記録 | 発射時の限界突破段階も記録。着弾前の持ち替えで通常攻撃属性・演出が別武器へ切り替わることを防止 |
| 限界突破素材 | オブジェクト参照比較による自動探索 | 別個体をGUI選択→確認→スロットとIDを再検証。対象自身の消費を防止 |
| アイテムLv | 管理コマンドなし | `/ccsadmin itemlevel <level> [player]`。EXPは0、サブステと限界突破は維持 |
| 強化 | 1個ずつ選択のみ | 全て選択／選択解除を追加。選択段階では消費しない。最大Lvでは素材を消費しない |
| 天賦発動場所 | 両手の3種類 | HOT_BAR／INVENTORY追加。武器ATK加算の範囲は従来どおり両手のみ |
| 所持天賦の検索範囲 | 両手のみ | HOT_BAR／INVENTORYが設定された場合だけ範囲を拡張。未使用なら両手だけを調べる |

## 追加キー・導入

- `config.yml: damage-chat.enabled`（初期false）
- `messages.yml: damage-chat.format`, `rebirth-failure.level`, `rebirth-failure.combat`, `command.itemlevel`
- `gui.yml: enhancement.select-all/select-all-lore/clear-selection/duplicate-title/duplicate-confirm-title/duplicate-confirm/no-duplicate/failure-reasons.*`
- `weapons.yml: weapons.ID.talent.hand`にHOT_BAR、INVENTORYを追加。
- `weapons.yml: weapons.ID.limit-breaks.0`～`.5`に武器と同じ構造の差分。マップは累積、リストは置換。
- 管理権限 `combatcoresystems.admin.itemlevel`（admin.*の子）。

追加表示キーは既存値を維持して自動補完されます。武器ID配下の例は自動追加しないため、同梱weapons.ymlのコメントとChatGPT用引き継ぎ書を参照して追加してください。更新はサーバーを正常停止→旧JARを退避→新JAR配置→起動の順。

## ChatGPTへ渡す資料

`ChatGPT-YAML-Handoff.md`と`ChatGPT-YAML-Reference.md`を同時に添付。後者はこのバージョンの既定YAMLと読み取り実装を収録しています。運用ファイルも添付するときは秘密情報を除いてください。

## 実機での確認が必要な点

BE実機、Geyser/Floodgateのバージョン、現地ログは未取得です。上記のコード修正だけで報告された全遅延・全ドロップ不発が解消したとは断定できません。

1. Java/BEでゲームモードを記録し、同一武器の`/ccs skill`と手からのドロップを比較。
2. `/ccsadmin debug on 2m`を実行。`drop`, `inventory click`, `drop skipped`, `cast attempt`, `cast rejected`を確認。
3. ドロップ系ログが全くない場合はGeyser側でイベントがサーバーへ到達しているか切り分け。
4. ブロック破壊も止まる場合はPaperのTPS/MSPT・プロファイラー結果と同時刻のログを確認。CCS以外の保護・スポーン保護・通信遅延も候補。
   素手・しゃがんでいない状態とも比較してください。スキル武器でのしゃがみ＋攻撃は従来から必殺技入力を優先し、通常操作をキャンセルします。
5. 限界突破では対象＋素材を別スロットへ置き、対象自身が候補にならないこと、確認した素材1本だけ減ることを検証。

この資料は改善点と未検証範囲を分けて記載しています。根本的な戦闘式・必要レベル100・ホットバーの同カテゴリ制限は変更していません。
