# CombatCoreSystems v1.4.6

## 変更前後と理由

| 対象 | 変更前 | 変更後 | 理由 |
|---|---|---|---|
| 装備の成長 | 定義ごとの任意値・部位外の候補も設定可能 | 部位・レア度別の固定成長表。獲得時に種類を抽選 | 個体ごとの成長を仕様表に一致させる |
| 既存装備 | 旧成長値を保持 | 初回読込時に新表へ移行。上限超過Lvを丸め、有効な種類を維持し、無効・重複を再抽選 | 旧個体も同じ規則で扱う |
| サブステータス | 旧初期値・強化増分 | Lv3/6/9/12で1種類開放。Lv3/6/9/12/15で未開放を含む候補を1回強化 | 確定した抽選ルールを再現 |
| 強化経験値 | 最大Lv到達後の余剰が消える | 100未満を切り捨て、同じ用途の数値素材として返却 | 素材の損失を防ぐ |
| 限界突破の説明 | 説明全体が黄色になる | 変更・追加された文字のみ黄色 | 差分を読み取りやすくする |
| 管理GUI | サブ値を自由入力 | 種類と強化回数を一覧から選択 | 固定表と操作を一致させる |
| 戦闘補正 | 能力値補正が中心 | 与被ダメージ、与被回復、種類別会心・属性変更を戦闘ごとに計算 | YAMLから技ごとの効果を表現する |
| 移動効果 | 共通の移動Actionなし | MOVE/DASH/LEAP/KNOCKBACK/PULL/TELEPORTと経路・終了時Action | 武器ごとのJava実装を不要にする |
| Bedrockでのインベントリ破棄 | 選択中スロットの破棄がスキル入力に変換されることがある | インベントリからの破棄は通常の破棄。手からの破棄はスキル | インベントリ操作を妨げない |
| 表示名 | 神心・回復力 | 追憶・治癒力 | ゲーム内の呼称を統一 |

装備のメイン候補は頭がHP/HP%/防御力/防御力%、胴が攻撃力/攻撃力%、脚が会心率/会心ダメージ、足がHP%/攻撃力%/防御力%/治癒力、残響が属性ダメージ/属性耐性。サブ候補はHP/HP%/防御力/防御力%/攻撃力/攻撃力%/会心率/会心ダメージの8種類。メインとサブの同種は許可し、サブ同士の重複は不可。★3はLv9・2種類、★4はLv12・3種類、★5はLv15・4種類が上限です。

治癒力は自然レベル上昇しない上級ステータス。回復は基礎回復量×(1+治癒力)×与回復補正×被回復補正で計算します。後方互換のため、設定・保存用の`HEALING_POWER`、`DIVINE_HEART`、`divine_hearts.yml`は維持します。

## YAMLと操作

[ChatGPT向けv1.4.6差分](ChatGPT-YAML-v1.4.6.md)に設定キーと例を記載。装備の旧`level-1`、`max-level`数値や`initial-substats`などは新しい個体の成長値を上書きしません。装備の`initial-level`は引き続き指定できます。

`/ccsadmin itemlevel`は装備のLvと、メイン・サブ・開放数・強化履歴を一緒に更新します。管理GUIのアイテム一覧は装備セット単位で分かれ、サブステータスの種類と強化回数はボタンで指定できます。

スキルは手に持つ武器のドロップ操作、必殺技はしゃがみ＋攻撃。Bedrockのインベントリ画面からの破棄はスキル扱いにしません。環境により「手からのドロップ」がサーバーイベントに届かない場合は、`controls.debug-inputs`を有効にして入力イベントを確認してください。

## 更新と検証

サーバー停止後、既存のプラグインデータとワールドをバックアップしてJARを交換してください。装備の旧個体は認識時に新方式へ移行するため、更新後に以前の成長値へ戻せるよう、保存データのバックアップを保管してください。表示文の既定値移行は既存の独自文を保持します。

Java単体テスト95件、YAML生成ロジック17ケース、Paper 26.2隔離サーバー試験134項目が成功しました。隔離試験ではMobと模擬プレイヤーを使用し、無人サーバーの移動試験のみMobの位置更新を補助しています。実クライアントを使うJava/Bedrock操作・表示と、多人数負荷は未検証です。
